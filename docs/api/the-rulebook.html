Documentation · Concepts

The rulebook

Every convention a drawing is held to lives in one object, SchematicRules, hanging off the document. The defaults are what an electronic schematic is expected to obey, so a fresh document behaves correctly with no configuration at all - and a host that wants a different convention changes one line.

Lines

document.Rules.AvoidParallelOverlap = true;   // no two wires share a lane
document.Rules.MinParallelGap       = 0;      // 0 = three quarters of a grid step
document.Rules.LaneSpacing          = 0;      // 0 = one grid step
document.Rules.MaxLateralLanes      = 6;      // how far sideways the search may look

Two wires that run together read as one thick line, and two that run four units apart read as one thick line as well. So "overlap" is not only "on top of": anything closer than MinParallelGap counts, which with the default puts every run on its own grid lane.

Parts

document.Rules.AvoidSymbols    = true;    // go round parts
document.Rules.SymbolClearance = 4;       // margin kept round a body
node.BlocksRouting             = false;   // this one part is not in the way

Parts a line is wired to are exempt automatically - a wire has to reach its own pins - and so are containers. A boundary or a package exists so that things sit inside it; treating one as solid would make everything in it unroutable, so a shape drawn round other shapes is worked out and left alone.

Dots

document.Rules.JunctionMinBranches = 3;       // three legs make a junction
document.Rules.JunctionMaxBranches = 4;       // more than four is reported, not drawn differently
document.Rules.JunctionOnTee       = true;    // a wire ending on a wire is a join
document.Rules.JunctionOnCrossing  = false;   // a crossing is not
document.Rules.CountPinsAsBranches = false;   // a pin is a terminal, not a branch
document.Rules.ConnectTouchingWires = true;   // touching a wire joins it

JunctionOnCrossing is off and deliberately so. Two lines that merely cross are not joined, and dotting them would claim a net that does not exist. Turn it on only for diagram styles where every crossing really is a join.

Editing

document.Rules.AllowSegmentDrag   = true;   // runs can be slid sideways
document.Rules.SnapSegmentsToGrid = true;   // and land on the grid when they are
document.Rules.PreserveEndStubs   = true;   // a wire never comes off a pin sideways
document.Rules.RotationStep       = 90;     // what one turn means

Two presets

document.Rules = SchematicRules.ForElectronics();   // identical to the defaults, named for intent
document.Rules = SchematicRules.ForDiagrams();      // nothing is dotted automatically

A mindmap has no notion of a solder joint, so the diagram preset stops drawing dots and stops treating a line that touches another line as joined to it. Lines still never stack, because that rule is about being readable rather than about electricity.

What is saved

Only the rules you changed. A document nobody re-configured writes no rules block at all, which means a later version of this library can improve a default and old files quietly follow it.
