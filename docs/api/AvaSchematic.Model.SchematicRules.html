Documentation · The rulebook

Model.SchematicRules

public sealed class Model.SchematicRules : Utils.ObservableObject

The drawing conventions a document is held to. Every value here already carries the default a schematic is expected to follow - wires never run on top of each other, a dot means a connection and never a crossing, three or four branches make a junction - so a fresh document behaves correctly without configuration, while a host that wants different conventions (a mindmap where crossings are dotted, a diagram where overlapping links are fine) can change any single rule.

Properties

bool AllowOverlapAtSharedEnds { get; set; }

Two lines that meet at a point are one net, so the stub they share on the way out of it is a single visible line rather than two stacked ones. Leaving this on keeps a schematic free of pointless jogs where several wires leave one pin.

bool AllowSegmentDrag { get; set; }

Lets a selected line be reshaped by dragging one of its segments sideways.

bool AvoidParallelOverlap { get; set; }

No two wires may run alongside each other on the same line. Routers score a candidate that would lie on top of an existing wire out of contention and step sideways into the next free lane instead. Crossing at a right angle is still allowed - that is the whole point of the junction rules below.

bool AvoidSymbols { get; set; }

A line may not be drawn across the body of a symbol. Crossing a part looks exactly like connecting to it, so the router treats every symbol as an obstacle and goes round, and a dragged segment steps aside rather than being dropped on top of one. Only the parts the line is actually attached to are exempt - a wire has to reach its own pins.

bool ConnectTouchingWires { get; set; }

A wire ending on the body of another wire is electrically joined to it (a tap). Turning this off makes touching a wire purely visual, so nothing is connected that was not wired explicitly.

bool CountPinsAsBranches { get; set; }

Whether a pin counts towards the branch total at a point. Off by default, because the dot marks a join between lines: a wire arriving at a pin is one line ending at one terminal and needs no dot, while three lines meeting there do. Turn it on for drawing styles that dot every terminal.

int JunctionMaxBranches { get; set; }

Largest branch count considered good practice. Anything above it is reported by RuleChecker rather than drawn differently.

int JunctionMinBranches { get; set; }

Branches that must meet - and be electrically joined - before a dot is drawn.

bool JunctionOnCrossing { get; set; }

Off by default and deliberately so: two lines that merely cross are not connected, and dotting them would claim a net that does not exist. Turn it on only for diagram styles where every crossing really is a join.

bool JunctionOnTee { get; set; }

Dot a wire that ends on the body of another wire. Requires SchematicRules.ConnectTouchingWires, since an unconnected touch is not a junction.

double LaneSpacing { get; set; }

Distance between two adjacent wire lanes. Zero means one grid step.

int MaxAvoidanceConnections { get; set; }

Sheets with more wires than this skip overlap avoidance, which is quadratic.

int MaxLateralLanes { get; set; }

How many lanes either side of the natural one a router may try.

double MinParallelGap { get; set; }

How close two wires of different nets may run alongside each other before the gap between them stops reading as two lines. Zero means three quarters of a grid step, so two runs that both landed on the grid are always far enough apart and anything squeezed between two grid lines is not.

double OverlapPenalty { get; set; }

Score added per world unit of parallel overlap. Well above the bend penalty, so a detour always beats an overlap.

double OverlapTolerance { get; set; }

How close two parallel wires must be before they count as running on top of each other, and how much overlap along the run is tolerated.

bool PreserveEndStubs { get; set; }

Dragging the segment that touches an attached end inserts a jog a short way along the wire instead of bending it right at the pin, so a wire never leaves a pin sideways.

double RotationStep { get; set; }

Degrees the rotate command turns a part by. Ninety keeps an electronic schematic on its axes; forty-five is what a diagram or a bridge-shaped part wants. Any value is allowed - the geometry, the pins and their normals all follow an arbitrary angle.

bool SnapSegmentsToGrid { get; set; }

—

double SymbolClearance { get; set; }

Margin kept around a symbol body, so a line never grazes the outline.

double SymbolPenalty { get; set; }

Score added per world unit of line drawn inside a symbol body.

Methods

Model.SchematicRules Clone()

—

static Model.SchematicRules ForDiagrams()

Diagram conventions: lines still never stack, but nothing is dotted automatically because a mindmap or an architecture chart has no notion of a solder joint.

static Model.SchematicRules ForElectronics()

The electrical conventions - identical to the defaults, named for intent.

double LaneSpacingFor(double gridSize)

Lane pitch for a document, falling back to the grid.

double ParallelGapFor(double gridSize)

The nearest a wire may pass another one it is not joined to. Falls back to three quarters of a grid step: close enough to allow two adjacent grid lanes, wide enough to reject a run that sits between them.

double SnapRotation(double degrees)

The nearest angle to degrees the SchematicRules.RotationStep allows, normalised to 0..360. Every command that turns a part goes through this, so a sheet drawn with a ninety degree step can never end up with a part at seventeen degrees.
